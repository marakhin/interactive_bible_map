# Библейская карта

Интерактивный русскоязычный атлас библейской истории. Он связывает время, событие, место, маршрут и точную ссылку на Священное Писание. Писание в продукте первично; исторические датировки, реконструкции маршрутов и спорные локализации визуально и текстово отделены от прямых утверждений библейского текста.

## Возможности

- интерактивная карта Восточного Средиземноморья на Leaflet с русскоязычной векторной подложкой MapLibre + OpenFreeMap/OpenMapTiles;
- 173 события от первых глав Бытия до прибытия апостола Павла в Рим;
- ссылки и встроенные отрывки только из 66 книг, общих для православных, католиков и протестантов;
- масштабируемая временная шкала без фиктивного нулевого года; на телефоне при выбранной книге лента эпох заменяется навигатором текущего события с переходами назад/вперёд;
- фильтр Ветхого и Нового Завета;
- полнотекстовый поиск по событиям, местам, людям и сюжетам;
- режимы персонажа, места и сюжетной линии;
- маршруты Авраама, Исхода, Давида, земного служения Господа Иисуса Христа и четырёх путешествий апостола Павла;
- карточки событий с первым разделом «Писание» и отдельными разделами истории и географии; на телефоне карточка сначала занимает около половины экрана, явно предлагает разворачивание, раскрывается до `77dvh` и скрывается свайпом вниз без снятия выделения точки и её подписи;
- иконка фильтра относится к слою карты и скрывается, пока открыт мобильный навигатор событий;
- традиционные локализации сохранены только в редакционных данных и не получают координат, пояснений или особого раздела в интерфейсе;
- понятные отметки неопределённости дат и локализаций;
- URL-состояние, адаптивный mobile-first интерфейс и manifest для установки приложения без offline-кэша.

## Стек

React 19, TypeScript, vinext/Vite, Leaflet, MapLibre GL JS, OpenFreeMap/OpenMapTiles, Zustand, Zod, Lucide React, Vitest и Playwright. Данные приложения локальны: backend, аккаунты и CMS не нужны. Векторные тайлы, glyphs и sprites текущей подложки загружаются с публичного сервера OpenFreeMap.

## Запуск

Требуется Node.js 22.13 или новее.

```bash
npm ci
npm run dev
```

Production-сборка:

```bash
npm run build
```

Русский style JSON отслеживается в репозитории. Генератор получает закреплённую ревизию подробного стиля OpenFreeMap Liberty, проверяет её SHA-256, ставит `name:ru` первым, затем английское/латинское и местное имя, и применяет приглушённую палитру. Для перегенерации нужна сеть; build выполняет только локальную проверку актуальности:

```bash
npm run map:style
npm run map:style:check
```

Unit-тесты и E2E:

```bash
npm test
npm run test:e2e
```

## Переменные окружения

Для текущего локального приложения обязательных переменных окружения нет. По умолчанию карта читает отслеживаемый стиль `/map/openfreemap-ru.json`; `NEXT_PUBLIC_MAP_STYLE_URL` позволяет заменить URL стиля без изменения компонента. Стандартный стиль использует публичные векторные тайлы, glyphs и sprites `tiles.openfreemap.org`, поэтому runtime-доступ к сети нужен. Автоматического возврата на растровую OSM-подложку нет; перед высоконагруженной production-публикацией следует выбрать подходящего провайдера или самостоятельное размещение и соблюдать условия OpenFreeMap, OpenMapTiles и OpenStreetMap.

## Структура данных

- `domain/types.ts` — типы и Zod-схемы.
- `domain/timeline.ts` — функции хронологии, сортировки и шкалы.
- `data/events.ts` — события и ссылки на Писание.
- `data/common-canon.ts` — проверяемый список 66 книг общего межконфессионального корпуса.
- `data/locations.ts` — места, координаты и статус локализации.
- `data/characters.ts` — персонажи.
- `data/storylines.ts` — сюжетные линии и порядок событий.
- `data/repository.ts` — `BibleDataRepository`, локальная реализация и перекрёстная проверка данных.

## Как добавить событие

Добавьте запись в массив `seeds` в `data/events.ts`. Обязательны уникальный `id`, название, Завет, книга из общего 66-книжного корпуса, ссылка вида `Быт. 12:1–9`, краткий пересказ только того, что сообщает текст, и хотя бы одна ссылка на Писание. Затем укажите существующие `locations`, `characters` и `stories`. Не включайте в `summary` богословские выводы или неподтверждённую реконструкцию.

## Как добавить место

Добавьте запись в `data/locations.ts`. Для известного места используйте `identified`. Для вероятного — `probable`, традиционного — `traditional`, спорного — `disputed`. Если точка неизвестна, не выдумывайте координаты: используйте `unknown` и оставьте широту/долготу пустыми. Каждая неочевидная локализация должна иметь ясное `localizationNoteRu`.

## Как добавить сюжет

Добавьте сюжет в `data/storylines.ts`, а его `id` — в `stories` соответствующих событий в требуемом порядке. `routeCertainty` имеет значения:

- `scriptural_sequence` — последовательность мест явно следует из текста;
- `approximate` — места следуют из текста, но линия между ними не является известной дорогой;
- `disputed` — маршрут или часть локализаций спорны.

## Неопределённые даты и география

- `relative` — событие находится в последовательности повествования, но не на светской шкале лет.
- `unknown` — календарное положение неизвестно.
- `approximate` — ориентировочная датировка, которая не является утверждением Писания.
- `range` — широкий диапазон вместо ложной точности.
- `certainty: disputed` — существуют существенно разные датировки.

Во внутреннем представлении отрицательные годы означают годы до Рождества Христова. Нулевой год запрещён и никогда не показывается пользователю.

Полные редакционные правила находятся в [DATA_GUIDE.md](./DATA_GUIDE.md).

## Перенос и публикация исходников

Полный технический паспорт, результаты проверок и порядок восстановления находятся в [PROJECT_DOCUMENTATION.md](./PROJECT_DOCUMENTATION.md).

После клонирования репозитория установите Node.js 22.13 или новее и выполните `npm ci`, `npm test`, `npm run build`, затем `npm run dev`. Обязательные секреты и переменные окружения для локального запуска не нужны. Зависимости, сборка и локальные логи исключены из Git.

Размещение исходников на GitHub само по себе не публикует работающий сайт. Текущая production-сборка предназначена для Worker/Sites; для GitHub Pages потребовалась бы отдельная адаптация.
