# Инструкции проекта

## Обязательная синхронизация документации

- `PROJECT_DOCUMENTATION.md` — главный технический паспорт и источник истины о текущем устройстве проекта.
- При каждом изменении исходников, данных, структуры каталогов, конфигурации, зависимостей, команд, тестов, интерфейса, runtime-поведения, интеграций, сборки или публикации обновляй `PROJECT_DOCUMENTATION.md` в рамках той же задачи.
- Обновляй все затронутые разделы, а не только журнал: дату и сводку, архитектуру и потоки, каталог файлов, модели и объёмы данных, зависимости, переменные окружения, команды, порядок восстановления, проверки, ограничения и известный технический долг.
- В конце каждого изменения добавляй краткую строку в раздел «Журнал изменений документации».
- Не объявляй изменение завершённым, пока документация не приведена в соответствие фактическому состоянию репозитория.
- Описывай только проверенные факты текущего кода. Неактивные, устаревшие и примерные части помечай явно.
- Сохраняй документацию на русском языке в UTF-8 и поддерживай инструкции восстановления так, чтобы проект можно было развернуть на новой машине только по отслеживаемым файлам и этому документу.

## Проверки

- После изменений выбирай проверки соразмерно риску; для обычных изменений TypeScript/данных минимум запускай `npm test` и `npm run build`.
- Для изменений интерфейса или карты дополнительно используй подходящие Playwright/browser-проверки.
- Не скрывай неуспешные проверки: фиксируй актуальный результат и причину в `PROJECT_DOCUMENTATION.md`.
- Перед редактированием библейского контента обязательно прочитай `DATA_GUIDE.md`.
